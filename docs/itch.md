# Offline ITCH reconstruction

`build/release/asterbook_itch FILE` and `python3 reference/itch.py FILE` consume an offline sequence of two-byte big-endian payload lengths followed by Nasdaq TotalView-ITCH 5.0 messages. The supported subset is A/F (add), E/C (execution), X (cancel), D (delete), and U (replace), according to [Nasdaq TotalView-ITCH 5.0](https://nasdaqtrader.com/content/technicalsupport/specifications/dataproducts/NQTVITCHSpecification.pdf), sections 1.3–1.4, accessed 2026-11-06. Prices are integer units of 1/10,000 dollars. Executions reduce the referenced displayed order; they are never sent to the matching engine.

This custom file framing is not SoupBinTCP or MoldUDP64. No sequence numbers, gap recovery, symbol directory, trading actions, trade statistics, broken trades, feed transport, or live market connection are implemented. Every unsupported type stops processing rather than silently skipping potentially meaningful updates. Input must be a complete, ordered, gap-free stream of only supported updates; a real feed contains other message types and requires an upstream filter that understands their semantics. Malformed lengths, unknown references, duplicate reference IDs, over-reductions, and inconsistent stock locates fail. Output is the final displayed orders, not a complete market picture. No market data is included.

The native `asterbook::itch::Reconstructor` also offers `apply_sequenced`: the caller supplies a monotonic sequence per supported message. A gap, duplicate, overflow or invalid message poisons the session until `reset()` clears all state. This application-level envelope is not an exchange transport protocol and does not recover missing messages. Limits default to one million live and two million seen references and can be set in the constructor. Validation errors preserve state; discard the instance after an allocation failure. Stock and attribution fields must contain printable ASCII.

For sequence validation from the CLI, `asterbook_itch --sequenced FILE` reads an eight-byte big-endian sequence before each two-byte length and payload. It stops on the first gap, duplicate or invalid message; start a new process with a fresh complete stream to reset.
